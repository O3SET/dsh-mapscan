fix: v1.7.2 — 修复插件挂载失败 (fiberPhase failed / 界面标红)

根因: 1.7.0 起 Config 需要 @deepseek-ai/schemastery 提供配置 schema, 而插件以
link:/junction 方式安装时, Node 会把符号链接解析到**仓库真实路径**再向上找
node_modules —— 干净克隆下仓库目录没有 node_modules, @deepseek-ai/schemastery
解析失败抛 ERR_MODULE_NOT_FOUND, 整个插件挂载失败, 界面上即显示为失败/标红。

本地测试之所以全绿, 是因为仓库根有 npm install 生成的 node_modules (含
schemastery), 恰好掩盖了真实安装场景 —— 这是本次排查最关键的教训。

修复: scripts/install.mjs 除安装插件本体外, 另在 profile 顶层
pnpm add @deepseek-ai/schemastery, 保证解析链上一定有它; 失败时给出可操作的手动
修复提示。手动重跑一次安装脚本即恢复 (已实测: 重跑后从已安装副本导入 dist 成功,
Config 判定为 schemastery)。

排查结论 (记录备查): 本机 profile 里 13 个断链 (dsh-client-web、cordis-plugin-hmr、
dsh-config-editor 等) 没有任何在装包声明依赖, 属 npx 缓存清理后的孤立残留, 不影响
启动; 控制台的 /plugins/events ERR_FAILED 与 /api/changes.summary 404 是该装配下的
既有现象, 与 MapScan 无关。

测试 90 例全绿。
